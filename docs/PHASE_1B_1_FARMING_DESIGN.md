## Executive Summary

Phase 1B-1 introduces the foundational tactile gameplay loop of `Living Village`: **tilling soil, sowing seeds, watering crops, and harvesting produce**.

In strict accordance with the project's technical architecture:
1. **Soil and crops remain non-ECS grid data**, stored in dense, contiguous $32 \times 32$ tile buffers inside `ChunkGrid`.
2. **The simulation remains 100% authoritative**. All farming interactions pass through the deterministic `PlayerCommand` pipeline (`TILL`, `SOW`, `WATER`, `HARVEST`).
3. **Biological growth and continuous moisture dynamics run on an efficient dual-cadence schedule**, avoiding wasteful 20Hz per-tick evaluations of static flora.
4. **Rendering is purely decoupled**. The client reads the `WorldRenderSnapshot` produced by the simulation and renders placeholder visuals without mutating state.
5. **No economy, NPC farmers, weather engines, or complex chemistry are introduced** in this phase.

```
Player Input (Keyboard/Mouse)
      ↓
PlayerCommand ('TILL', 'SOW', 'WATER', 'HARVEST')
      ↓
Authoritative WorldSimulation (Validation & Execution at Tick Boundary)
      ├─► ChunkGrid (TileData: terrainType, moisture, fertility, cropStage, matureDays, dryDays)
      ├─► InventoryComponent (Player seeds, tools, harvest yield)
      └─► SimEvents (SOIL_TILLED, CROP_SOWN, SOIL_WATERED, CROP_HARVESTED)
      ↓
WorldRenderSnapshot (Exported read-only presentation slice)
      ↓
PixiJS Client (Visual presentation of tilled furrows, moisture tints, crop stages)
```

## 1. Soil Model & Continuous Moisture Dynamics

### 1.1 Soil State in ChunkGrid
Soil state is stored directly within `TileData` inside `WorldChunk` ($32 \times 32$ tiles per chunk). Soil is **not** an ECS entity.

```typescript
export interface TileData {
  terrainType: number;     // 0=Grass, 1=Dirt, 2=TilledSoil, 3=Stone, 4=Water
  elevation: number;       // 0-255 height level
  flags: number;           // Bitmask: WALKABLE, WATER, OCCUPIED_BY_STRUCTURE, TILLED
  moisture: number;        // 0 (Bone Dry) to 100 (Fully Saturated)
  fertility: number;       // 0 (Barren/Depleted) to 100 (Rich Organic Loam)
  cropTypeId: number;      // 0 = None, 1..N = Registered Crop Type
  cropStage: number;       // 0=Seed, 1=Sprout, 2=Growing, 3=Mature, 4=Wilted
  cropProgress: number;    // 0-255 sub-stage progress
  growthDays: number;      // Cumulative watered days completed in current growth stage
  matureDays: number;      // Consecutive in-game days spent in Stage 3 Mature state
  dryDays: number;         // Consecutive in-game days with moisture < MIN_GROWTH_MOISTURE
}
```

### 1.2 Soil Attributes & Physical Ranges

| Attribute | Range | Baseline | Description |
| :--- | :--- | :--- | :--- |
| **`moisture`** | `0 – 100` | `0` (Dry) | Continuous water saturation level. Hard-clamped to $[0, 100]$. |
| **`fertility`** | `0 – 100` | `50` (Loam) | Organic soil nutrients. Depleted by crops upon harvest; regenerated by fallow resting. |
| **`terrainType`** | `0 – 4` | `0` / `1` | Transition from `Grass (0)` or `Dirt (1)` to `TilledSoil (2)` unlocks agricultural interactions. |
| **`flags`** | Bitmask | `1` | `TILE_FLAGS.TILLED (1 << 3)` is set when tilled. Walkability remains `WALKABLE`. |
| **`growthDays`** | $\ge 0$ | `0` | Tracks daily watered progress toward the next crop stage. |
| **`matureDays`** | $\ge 0$ | `0` | Tracks consecutive days spent ripe in Stage 3 before wilting. |
| **`dryDays`** | $\ge 0$ | `0` | Tracks consecutive drought days before crops wilt. |

### 1.3 Continuous Moisture Model
The moisture model is **continuous and physical**. Moisture is **never artificially reset to an arbitrary baseline at dawn**.

1. **Initial Moisture:**
   - Untilled natural soil and freshly hoed dirt start at `0` (bone dry).
2. **Manual Watering:**
   - Applying the watering can adds $+100$ moisture, clamped to $100$:
     $$\text{moisture} = \min(100, \text{moisture} + \text{WATERING\_CAN\_MOISTURE\_AMOUNT})$$
3. **Rain Precipitation:**
   - When external rain is active, rain continuously infiltrates uncovered tiles every in-game hour:
     $$\text{moisture} = \min(100, \text{moisture} + \text{RAIN\_MOISTURE\_PER\_HOUR} \times \text{intensity})$$
4. **Hourly Evaporation (Continuous Decay):**
   - Every in-game hour ($1,200$ ticks), soil loses moisture to the atmosphere:
     $$\text{moisture} = \max(0, \text{moisture} - \text{HOURLY\_EVAPORATION\_RATE})$$
   - On a standard sunny day without rain, a fully watered furrow ($100$) loses $2 \times 24 = 48$ moisture points across 24 in-game hours, ending the day at $52$. Moisture carries over continuously into the night and next morning!
5. **Crop Moisture Uptake:**
   - At the daily dawn evaluation (06:00 AM), an actively growing crop (stages 0, 1, 2) absorbs hydration:
     - If $\text{moisture} \ge \text{MIN\_GROWTH\_MOISTURE}$ ($20$):
       $$\text{moisture} = \max(0, \text{moisture} - \text{CROP\_DAILY\_MOISTURE\_CONSUMPTION})$$
       The crop counts as **watered** for that day (`growthDays++`, `dryDays = 0`).
     - If $\text{moisture} < \text{MIN\_GROWTH\_MOISTURE}$ ($20$):
       The crop is **water-stressed** and cannot grow (`dryDays++`, `growthDays` does not advance). The remaining trace moisture is not consumed.
6. **Zero Moisture State (Bone Dry):**
   - When $\text{moisture} = 0$, biological growth stops.
   - If an active crop suffers $\text{dryDays} \ge \text{MAX\_DROUGHT\_DAYS}$ ($3$ consecutive dry days), it withers into Stage 4 (`Wilted`).
   - If an unseeded tilled furrow remains at $\text{moisture} = 0$ for $\text{FALLOW\_DEGRADE\_DAYS}$ ($2$ consecutive days), the furrow collapses and reverts to untilled `Dirt (1)`.
7. **Overwatering Rule:**
   - Moisture is hard-clamped at $100$. Overwatering penalties (fungal root rot) are explicitly **deferred** to preserve intuitive early gameplay.

## 2. Crop Growth Life Cycle (Strict 5-Stage Model)

The crop model strictly maintains **5 discrete stages** ($0$ to $4$). No sixth stage is introduced.

```
[Stage 0: Seed] ──► [Stage 1: Sprout] ──► [Stage 2: Growing] ──► [Stage 3: Mature] ──► [Stage 4: Wilted]
```

### 2.1 Stage Definitions & Transition Rules

| Stage | Name | Visual Representation | Daily Hydration Required? | Harvest Allowed? | Transition Trigger |
| :---: | :--- | :--- | :---: | :---: | :--- |
| **0** | **Seed** | Furrow with seed dots | Yes ($\ge 20$) | **No** | Advances to **Stage 1** when `growthDays >= stageDays[0]` |
| **1** | **Sprout** | Small green shoot | Yes ($\ge 20$) | **No** | Advances to **Stage 2** when `growthDays >= stageDays[1]` |
| **2** | **Growing** | Leafy vegetative cluster | Yes ($\ge 20$) | **No** | Advances to **Stage 3** when `growthDays >= stageDays[2]` |
| **3** | **Mature** | Full ripe plant with produce glow | No | **YES** | Holds ripe state. Transitions to **Stage 4** when `matureDays >= MAX_UNHARVESTED_DAYS` |
| **4** | **Wilted** | Gray-brown drooping dead stalk | No | **No** (Clear only) | Terminal state. Clearing yields biomass/fiber. Auto-decays after 5 days into mulch. |

### 2.2 The Mature-State Counter (`matureDays`)
To allow mature crops to remain harvestable across multiple in-game days without creating an extra stage:
1. When a crop enters **Stage 3 (Mature)**:
   - `cropStage = 3`, `growthDays = 0`, `matureDays = 0`.
   - The crop is fully harvestable via the `HARVEST` command.
2. At every subsequent daily dawn evaluation:
   - If `cropStage === 3`, `matureDays` increments by 1.
   - Mature crops do **not** require daily watering to remain harvestable.
3. If $\text{matureDays} \ge \text{MAX\_UNHARVESTED\_DAYS}$ ($5$ in-game days):
   - The unharvested produce rots in the field.
   - `cropStage` transitions from **3 (Mature)** to **4 (Wilted)**.
   - `matureDays` resets to $0$.

### 2.3 Drought Wilting Rule
If a crop in vegetative stages (**0, 1, or 2**) experiences $\text{dryDays} \ge \text{MAX\_DROUGHT\_DAYS}$ ($3$ consecutive days without adequate moisture):
- The crop dies of dehydration.
- `cropStage` transitions directly to **4 (Wilted)**.

### 2.4 Reference Crop Definition: Parsnip (`cropTypeId = 1`)
```typescript
export interface CropDefinition {
  readonly id: number;
  readonly name: string;
  readonly seedItemId: string;
  readonly harvestItemId: string;
  readonly totalDaysToMature: number;     // 4 watered days
  readonly stageDays: readonly number[];  // [1, 1, 2] -> Seed: 1 day, Sprout: 1 day, Growing: 2 days
  readonly dailyMoistureNeed: number;     // 20 moisture points
  readonly fertilityConsumption: number;  // 15 fertility points
  readonly baseYieldMin: number;          // 1
  readonly baseYieldMax: number;          // 2
}
```

## 3. Game Time & Temporal Architecture

### 3.1 Proposed Temporal Scale Analysis

| Parameter | Default Proposed Setting | Rationale & Player Experience |
| :--- | :--- | :--- |
| **Simulation Rate** | `20Hz (50ms per tick)` | Standard deterministic engine rate established in Phase 1A. |
| **In-Game Day Length** | `24.0 real minutes` ($28,800$ ticks) | Exactly $1.0\text{ real minute}$ per in-game hour. Provides ample time for travel, farming, villager dialogue, and stamina management without frantic rushing. |
| **Parsnip Growth Time** | `4 in-game days` ($96\text{ real minutes}$) | Represents ~1.5 hours of continuous play. With bed sleep skipping night hours (22:00 to 06:00), active daytime is ~16 real minutes/day, allowing a 4-day crop to mature in **~64 minutes of active play**. |
| **Pausing Behavior** | Total simulation freeze | When the game is paused (`sim.pause()`), virtual time, commands, hourly evaporation, and dawn biological growth completely halt. |
| **Sleeping Behavior** | Deterministic Fast-Forward | Sleeping triggers an authoritative command (`SLEEP`) advancing `clock.currentTick` forward to dawn (06:00), processing intermediate hourly evaporation and dawn growth in sequence. |

### 3.2 Configurable Time Architecture (`TIME_CONFIG`)
The time conversion is **never hardcoded**. All temporal relationships derive from configurable constants:

```typescript
export const TIME_CONFIG = {
  // [TUNABLE] Engine tick frequency
  TICKS_PER_SECOND: 20,

  // [TUNABLE] Real seconds per virtual in-game minute
  SECONDS_PER_IN_GAME_MINUTE: 1.0,

  // [TUNABLE] In-game minutes per in-game hour
  MINUTES_PER_IN_GAME_HOUR: 60,

  // [TUNABLE] In-game hours per in-game day
  HOURS_PER_IN_GAME_DAY: 24,

  // [TUNABLE] Dawn evaluation hour when daily crop growth occurs
  DAWN_HOUR: 6,

  // Derived constants
  get TICKS_PER_IN_GAME_HOUR(): number {
    return this.TICKS_PER_SECOND * this.SECONDS_PER_IN_GAME_MINUTE * this.MINUTES_PER_IN_GAME_HOUR; // 1,200
  },
  get TICKS_PER_IN_GAME_DAY(): number {
    return this.TICKS_PER_IN_GAME_HOUR * this.HOURS_PER_IN_GAME_DAY; // 28,800
  }
} as const;
```

## 4. Farming Actions & Interaction Model

Farming actions pass through the authoritative `CommandQueue`. The client sends input intentions; the simulation validates Euclidean proximity, tool requirements, and tile conditions before executing mutations.

### 4.1 Tunable Euclidean Interaction Reach
Interaction radius is not hardcoded. It uses Euclidean distance measured from the player's center to the target tile's center:

$$\text{distance} = \sqrt{(x_{\text{player}} - (x_{\text{tile}} + 0.5))^2 + (y_{\text{player}} - (y_{\text{tile}} + 0.5))^2} \le \text{INTERACTION\_REACH\_TILES}$$

```
                ▲ y
                │
         [ ]   [N]   [ ]       Cardinal Reach: (0, 1)  -> dist = 1.000 ≤ 1.500 (Allowed)
          ▲     ▲     ▲        Diagonal Reach: (1, 1)  -> dist = 1.414 ≤ 1.500 (Allowed)
          │     │     │        2-Tile Reach:   (0, 2)  -> dist = 2.000 > 1.500 (REJECTED)
   ───► [W] ── [P] ── [E] ──► x
                │
               [S]
```

- When `INTERACTION_REACH_TILES = 1.5` (default), all 4 cardinal neighbors and all 4 diagonal neighbors are reachable.
- If tuned to $1.2$, diagonals ($\sqrt{2} \approx 1.414$) are automatically excluded, enforcing strict 4-directional cardinal interaction.

### 4.2 Action Matrix

| Command | Tool / Item Required | Preconditions | State Mutations | Failure Code |
| :--- | :--- | :--- | :--- | :--- |
| **`TILL`** | `tool_hoe` in inventory | - Distance $\le \text{reach}$<br>- Tile is `Grass (0)` or `Dirt (1)`<br>- Tile is `WALKABLE` | - `terrainType = 2`<br>- `flags \|= TILE_FLAGS.TILLED`<br>- Emits `SOIL_TILLED` | `OUT_OF_RANGE`<br>`INVALID_TERRAIN`<br>`ALREADY_TILLED`<br>`MISSING_TOOL` |
| **`SOW`** | `seed_parsnip` (qty $\ge 1$) | - Distance $\le \text{reach}$<br>- Tile is `TilledSoil (2)`<br>- `cropTypeId === 0` | - `cropTypeId = seedDef.cropId`<br>- `cropStage = 0`, `growthDays = 0`<br>- Deduct 1 seed from inventory<br>- Emits `CROP_SOWN` | `OUT_OF_RANGE`<br>`NOT_TILLED`<br>`TILE_OCCUPIED`<br>`NO_SEEDS` |
| **`WATER`** | `tool_watering_can` (charges $> 0$) | - Distance $\le \text{reach}$<br>- Tile is `TilledSoil (2)` or active crop<br>- Can has $\ge 1$ charge | - `moisture = min(100, moisture + 100)`<br>- Can charges $-= 1$<br>- Emits `SOIL_WATERED` | `OUT_OF_RANGE`<br>`NOT_TILLED`<br>`CAN_EMPTY`<br>`MISSING_TOOL` |
| **`HARVEST`** | Empty hand or sickle | - Distance $\le \text{reach}$<br>- `cropTypeId > 0`<br>- `cropStage === 3` (Mature) OR `4` (Wilted)<br>- Inventory has space | - If Mature: add crop produce, deduct fertility, reset tile to $0$<br>- If Wilted: add fiber, reset tile to $0$<br>- Emits `CROP_HARVESTED` | `OUT_OF_RANGE`<br>`NOT_MATURE`<br>`NO_CROP`<br>`INVENTORY_FULL` |

## 5. Rain & External Environment Interface

The farming system **does not implement weather simulation** (e.g. pressure systems, wind, thunder). It depends exclusively on a clean external contract:

```typescript
export interface IEnvironmentProvider {
  /**
   * Returns true if active precipitation is falling at the given tick.
   */
  isRaining(currentTick: number): boolean;

  /**
   * Returns rain precipitation intensity between 0.0 (mist) and 1.0 (downpour).
   */
  getRainIntensity(currentTick: number): number;
}
```

During hourly updates, the simulation checks `environment.isRaining(tick)`:
- If raining, all open exterior chunk tiles receive $+25 \times \text{intensity}$ moisture points.
- If not raining, normal atmospheric evaporation occurs ($-2$ moisture points).

## 7. Soil Fertility & Nutrient Consumption

1. **Consumption on Harvest:**
   - At harvest, mature crops deplete soil fertility:
     $$\text{fertility} = \max(0, \text{fertility} - \text{cropDef.fertilityConsumption})$$
   - Continuous replanting without rest reduces fertility toward $0$.
2. **Quality & Yield Scaling:**
   - High fertility boosts produce quality tier and bonus yield using `sim.rng`:
     - $\text{fertility} < 30$: Standard quality ($100\%$), yield = $1$.
     - $30 \le \text{fertility} \le 69$: Standard ($70\%$), Fine ($30\%$), yield = $1 – 2$.
     - $\text{fertility} \ge 70$: Fine ($60\%$), Masterwork ($40\%$), yield = $2$.
3. **Fallow Regeneration:**
   - Untilled soil below natural baseline ($50$) resting across a seasonal boundary regenerates $+15$ fertility naturally, capping at $50$.
   - **Boundary Architecture:** A future Calendar/World system is responsible for determining season transitions and explicitly invokes the authoritative farming fallow-recovery boundary (`sim.triggerSeasonalFallowRecovery()` / `farming.applyFallowRecovery(chunkGrid)`). The Phase 1B-1 farming subsystem does not independently track, dictate, or advance calendar seasons.

## 8. Save / Load Persistence Specification

### 8.1 Persisted Fields
All agricultural state resides inside `TileData` in `ChunkGrid` and `InventoryComponent` in `ECSWorld`:

```typescript
// ChunkGrid: TileData (per tile in each 32x32 chunk)
terrainType: number;     // uint8
elevation: number;       // uint8
flags: number;           // uint8 (includes TILE_FLAGS.TILLED)
moisture: number;        // uint8 (0-100)
fertility: number;       // uint8 (0-100)
cropTypeId: number;      // uint16 (0 = None, 1 = Parsnip)
cropStage: number;       // uint8 (0-4)
cropProgress: number;    // uint8 (0-255)
growthDays: number;      // uint8
matureDays: number;      // uint8
dryDays: number;         // uint8

// ECSWorld: Player InventoryComponent
slots: Array<{ itemId: string; quantity: number; charges?: number } | null>;

// SimClock
currentTick: number;     // uint32
```

### 8.2 SaveSchema Compatibility
Because `SaveSchema` serializes `ChunkSnapshot.tiles` as an array of JSON objects, adding `growthDays`, `matureDays`, and `dryDays` to `TileData` maintains **100% backward and forward compatibility** with `SaveManager`, `NodeCryptoHasher`, and `BrowserSha256Hasher`.

## 9. Determinism Specification

To guarantee that multiplayer (in future phases) and replay logs remain bit-for-bit identical across all platforms:

1. **Strict Tile Iteration Order:**
   - Always iterate chunks in deterministic chunk order: $y \times \text{width} + x$.
   - Always iterate tiles within a chunk in row-major order:
     $$\text{tileIndex} = \text{localY} \times 32 + \text{localX}$$
2. **Command Processing Order:**
   - Scheduled player commands are sorted deterministically by `commandId` before execution.
3. **Randomness Governance:**
   - All random rolls (harvest yield count, crop quality tier) consume `sim.rng` (`DeterministicRng`).
   - `Math.random()` and `Date.now()` are **strictly prohibited** in all simulation modules.

## 12. Strict Scope Boundaries

To prevent scope creep, the following remain **explicitly excluded** from Phase 1B-1:
- **NO NPC Farmers:** Village NPCs do not farm.
- **NO Economy or Trading:** No merchants, shop screens, or gold.
- **NO Complex Weather:** Only the minimal `IEnvironmentProvider` rain boolean.
- **NO Fertilizer Crafting:** Composting is deferred to Phase 1B-2.
- **NO Genetics or Hybridization:** Crops are static definitions.
- **NO Automatic Irrigation:** No pipes, sprinklers, or aqueducts.
- **NO Final Art / Audio:** Simple geometric presentations only.
